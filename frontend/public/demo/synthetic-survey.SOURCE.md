# Synthetic ordinal survey: provenance and reproduction

This teaching example contains **no participant data**. Its 1,500 synthetic respondents have Likert responses and demographic information. The item responses come from the existing `mixed` fixture generated by `frontend/scripts/efa-reference/generate.R` with seed `73021`. The generator simulates correlated factors, item noise and a cross-loading, then cuts the simulated continuous values into ordered categories. The eight renamed survey items retain the values and row order used in the independent R comparison. `Organize` and `Invent` use three levels, and the other items use five. Higher categories represent greater endorsement in this illustration. It is not a validated psychometric instrument or the SAPA/IPIP response dataset.

`ResponseID` numbers the synthetic respondents from 1 through 1,500 in source order. The generator also appends two synthetic demographic attributes. A separate Mulberry32 stream seeded with `73022` makes two draws per row in source order. The first assigns Woman and Man with 47.5% probability each and Nonbinary with 5% probability. In the generated sample, 722 respondents are women, 692 are men and 86 are nonbinary. The second selects a whole-number age from 18 through 80 with equal probability. Both draws are independent of the item responses. These distributions were chosen for the plotting exercise. Only the eight survey items enter the fit and scoring. Marker color in the factor-score plot shows Gender.

From the repository root, rebuild and compare without editing the bundled asset:

```sh
node frontend/scripts/generate-demo-survey.mjs | cmp - frontend/public/demo/synthetic-survey.csv
```

The walkthrough imports the 1,500-row survey with a 70/30 split using Mulberry32 seed 2026. Only the 1,050 Development respondents enter the EFA and score plot. Full and Holdout stay locked. The model fits two factors with polychoric correlations, MINRES and Promax. The eight items have complete responses.

The Development reference in `frontend/src/lib/__tests__/fixtures/efa/demo-development.reference.json` records the input and membership digests, rotated pattern and regression weights. To regenerate it, export the Development table, save its ResponseID column in source order as one integer per line, and run `Rscript frontend/scripts/efa-reference/demo-development.R frontend/public/demo/synthetic-survey.csv development-ids.txt` in the pinned R reference environment. The membership digest covers the compact JSON array of zero-based original row positions.

With the preview running, `node frontend/scripts/check-teammate-demo.mjs http://localhost:3011` checks the original input, fitting and plotted membership in the record. On a preview with the diagnostic bridge, it also checks each plotted coordinate against the R weights using Development means and sample standard deviations. The comparison allows equivalent factor orders and signs. The original 1,500-row numerical benchmark remains in `mixed.reference.json`.
